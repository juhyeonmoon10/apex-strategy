# COMPOUND — 웹디자인 기획서

F1 타이어 전략 시뮬레이터 v3 · 화면 설계
15팀 컴파운드 · 2026-08-28

> 이 문서는 **화면과 경험**만 다룹니다. 시뮬레이션 엔진, 데이터 파이프라인, 분석 방법은
> 기존 자산을 그대로 씁니다(`src/engine/`, `tools/`, `data/`). 여기서 정하는 것은
> "무엇을 보여줄 것인가"와 "어떻게 보이게 할 것인가"입니다.

## 0. 한 페이지 요약

| 항목 | 결정 |
|---|---|
| **이름** | **COMPOUND** — 팀 이름과 같음. F1에서 '컴파운드'는 타이어 배합이자 이 프로젝트의 주제 |
| **한 줄 정의** | F1 타이어 전략을 **한국어로, 근거와 함께** 이해하게 만드는 시뮬레이터 |
| **핵심 사용 맥락** | ① 학술제 발표 시연 (심사위원·관객) ② 팀원 개인 탐색 ③ 보고서 첨부 링크 |
| **구조** | 4개 페이지 — 홈 / 시뮬레이터 / 연구 / 팀 |
| **시뮬레이터 방식** | **3단계 스텝 흐름** (조건 → 전략 → 레이스). 한 화면에 한 질문 |
| **비주얼** | 다크 기반, 채도는 컴파운드 색만. 팀 컬러는 정체성 영역 한정 |
| **기술** | 무빌드 정적 HTML + ES 모듈. GitHub Pages |
| **마감** | 10/30 (11회차) — 발표 2주 전 완성 |

## 1. 왜 다시 설계하는가

v2는 기능적으로 완성됐지만 **한 페이지에 7개 섹션을 세로로 쌓은 대시보드**였습니다.
써보면서 드러난 문제:

| 문제 | 증상 |
|---|---|
| **진입 장벽** | 첫 방문자가 조건·추천·빌더·트레이스·차트·근거·분포를 한꺼번에 봄. 어디부터 볼지 모름 |
| **근거가 묻힘** | 우리 차별점인 "왜 이 전략인가" 설명이 7개 중 6번째 섹션. 스크롤을 한참 내려야 나옴 |
| **발표에 부적합** | 시연할 때 스크롤로 오르내리면 관객이 흐름을 놓침. 단계별로 보여줄 수 없음 |
| **연구 내용이 없음** | 학술제에서는 "어떻게 만들었나"가 결과만큼 중요한데, 사이트에 데이터·방법·검증 페이지가 없음 |
| **정체성 약함** | 경쟁 서비스(PITWALL, TracingInsights)와 구분되는 시각적 개성이 없음 |

v3의 방향은 **"대시보드"에서 "안내된 경험"으로**입니다.

## 2. 사용자와 사용 맥락

### 2-1. 누가 보는가

| 사용자 | 상황 | 원하는 것 | 디자인 요구 |
|---|---|---|---|
| **심사위원·관객** | 학술제, 5~10분 시연 관람 | 뭘 만들었는지, 왜 의미 있는지 즉시 이해 | 첫 화면에서 가치 전달. 단계별 시연 가능 |
| **팀원 (발표자)** | 무대에서 시연 | 실수 없이 순서대로 보여주기 | 스텝 흐름. 뒤로/앞으로 명확. 큰 글씨 |
| **선생님·평가자** | 보고서 링크로 접속 | 연구 과정·데이터·검증 확인 | 연구 페이지. 실제 숫자. 재현 방법 |
| **F1 팬 (일반)** | 검색 유입 | 내 팀 전략 시뮬레이션 | 팀 선택 → 바로 결과 |

**설계의 우선순위는 위 표의 순서입니다.** 학술제가 첫째입니다.

### 2-2. 사용 환경

| 환경 | 비율(예상) | 대응 |
|---|---|---|
| 발표용 빔프로젝터 (1920×1080, 밝은 강당) | 시연 시 100% | **명도 대비를 강하게**. 12px 이하 텍스트 금지 |
| 노트북 (1366~1536 폭) | 팀원 작업 | 1280 기준 설계 |
| 모바일 | 링크 공유 시 | 스텝 흐름이 모바일에 자연스럽게 맞음 |

> 빔프로젝터는 다크 UI의 어두운 회색을 뭉개버립니다. `--fg-tertiary`(#5F6672) 같은 저대비
> 텍스트는 발표 화면에서 안 보입니다. **발표 모드**에서는 대비를 한 단계씩 올립니다(7절).

## 3. 정보 구조

```
compound/
├── index.html          홈 — 한 문장, 시연 진입, 연구 요약
├── sim.html            시뮬레이터 — 3단계 스텝
├── research.html       연구 — 데이터·방법·검증·한계
└── team.html           팀 — 5명, 역할, 일정
```

4개 페이지, 각각 독립 HTML. 해시 라우팅보다 **URL이 명확**하고, 발표 중 특정 페이지로
바로 갈 수 있습니다. 공통 헤더·푸터는 JS로 주입합니다.

### 페이지별 역할

| 페이지 | 답하는 질문 | 핵심 요소 |
|---|---|---|
| **홈** | 이게 뭐고 왜 만들었나? | 히어로 문장, 시연 시작 버튼, 숫자 3개(23,048랩 · MAE 0.717초 · 오차 0.7%) |
| **시뮬레이터** | 이 조건에서 어떤 전략이 좋은가, 왜? | 스텝 1 조건 → 스텝 2 전략+근거 → 스텝 3 레이스 재생 |
| **연구** | 어떻게 만들었고 얼마나 믿을 수 있나? | 데이터 파이프라인, 전처리 표, 회귀 결과, 검증, 한계, 선행연구 |
| **팀** | 누가 했나? | 5명 카드, 역할, 회차별 진행 |

## 4. 시뮬레이터 — 3단계 스텝 흐름

v3의 핵심 설계 결정입니다. 대시보드를 **세 화면으로 쪼갭니다.**

```
 ┌──────────┐     ┌──────────┐     ┌──────────┐
 │ 1 조건   │ ──▶ │ 2 전략   │ ──▶ │ 3 레이스 │
 │          │ ◀── │          │ ◀── │          │
 └──────────┘     └──────────┘     └──────────┘
   서킷·팀         추천 3안         트레이스
   날씨·그리드     + 근거           + 재생
                   + 빌더           + 확률
```

각 단계는 **한 화면에 딱 맞습니다** (1080p 기준 스크롤 없음). 상단 스텝 표시기로
어디 있는지 항상 보이고, 하단 버튼으로 앞뒤 이동합니다.

### 4-1. 스텝 1 — 조건

```

│ COMPOUND                              ● 1 조건  ○ 2 전략  ○ 3 레이스    │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   어디서, 누가, 어떤 날씨에 달리나요?                                   │
│                                                                         │
│   ┌──────────────────────────┐   ┌────────────────────────────────────┐ │
│   │  서킷                    │   │                                    │ │
│   │  ┌────────────────────┐  │   │      [드라이버 사진]               │ │
│   │  │ 영국 그랑프리   ▾  │  │   │                                    │ │
│   │  └────────────────────┘  │   │      63  George Russell            │ │
│   │  실버스톤 · 52랩         │   │      Mercedes                      │ │
│   │  ✓ 실측 캘리브레이션     │   │                                    │ │
│   │                          │   │      [머신 이미지]                 │ │
│   │  팀 / 드라이버           │   │                                    │ │

- 왼쪽 입력, 오른쪽 즉시 반영되는 가라지. 팀을 바꾸면 사진·차·테마가 따라 바뀜
- 서킷 옆 **"✓ 실측 캘리브레이션"** 배지 — 실버스톤에만 붙음. 나머지 서킷은 "근사 초기값" 표시. **정직함이 디자인 요소**
- 고급 설정(기온·습도·트래픽)은 접힘. 발표 때 안 건드릴 것들은 숨김

- 카드를 클릭하면 아래 근거가 그 전략으로 바뀜

- 전략 빌더는 **접힘 상태**로 시작. 펼치면 드래그 타임라인이 나옴. 발표에서는 "직접 바꿔보면…"으로 한 번 펼쳐 보여줌
- 용어(언더컷·클리프·오버컷)에 점선 밑줄 + 툴팁 유지

## 5. 홈 페이지

첫 화면에서 5초 안에 "뭔지" 전달해야 합니다.

```

│                                                                         │
│        F1 타이어 전략을                                                 │
│        한국어로, 근거와 함께.                                           │
│                                                                         │
│        실제 23,048랩 데이터로 캘리브레이션한 시뮬레이터가               │
│        어떤 전략이 빠른지, 그리고 왜 빠른지 설명합니다.                 │
│                                                                         │
│        [ 시뮬레이션 시작 → ]     [ 연구 보기 ]                          │

## 7. 비주얼 시스템

### 7-1. 색

v2의 규칙을 유지합니다: **채도는 컴파운드가, 정체성은 팀이.**

```css
/* 바탕 — 무채색 4단 */
--bg-0: #0A0B0D;     /* 페이지 */
--bg-1: #131519;     /* 카드 */
--bg-2: #1C1F25;     /* 입력, 상승 요소 */
--bg-3: #262A32;     /* 호버, 선택 */

/* 글자 */
--fg-0: #F2F4F7;     /* 본문·제목 */
--fg-1: #9BA3AF;     /* 보조 */
--fg-2: #5F6672;     /* 캡션 — 발표 모드에서는 #8A929E로 승격 */

/* 컴파운드 — 데이터 영역 전용. 이 다섯 색 외에 채도 있는 색은 팀 컬러뿐 */
--soft:   #DA291C;
--medium: #FFD12E;
--hard:   #F0F0EC;
--inter:  #43B02A;
--wet:    #0067AD;

/* 팀 — 런타임 주입. 헤더·버튼·포커스·가라지에만 */
--team, --team-on, --team-cta, --team-data   (v2 theme.js 규칙 그대로)
```

**발표 모드** (`?present=1` 또는 헤더 토글):
- `--fg-2`를 `#8A929E`로 (대비 4.5:1 → 6.2:1)
- 본문 15px → 17px, 근거 문장 17px → 20px
- 카드 테두리 `--border` → `--border-strong`
- 애니메이션 시간 1.5배 (관객이 따라올 수 있게)

### 7-2. 타이포그래피

| 용도 | 서체 | 크기 | 무게 |
|---|---|---|---|
| 페이지 제목 | Barlow Condensed | 44px | 700 |
| 섹션 제목 | Barlow Condensed | 28px | 700 |
| 카드 제목 | Barlow Condensed | 20px | 700 |
| 본문 | Pretendard → Noto Sans KR | 15px | 400 |
| 근거 문장 | Pretendard | 17px | 400, 숫자 600 |
| 숫자 (모든 수치) | JetBrains Mono | 문맥 | 500, `tabular-nums` |
| 캡션·라벨 | Pretendard | 12px | 500, `letter-spacing: 0.04em` |

- **한글 본문은 Pretendard 우선.** Noto Sans KR보다 자간이 단정하고 숫자와 어울림. CDN 로드, 실패 시 Noto → system-ui
- 12px 미만 텍스트 **금지**. 빔프로젝터에서 안 읽힘
- 숫자는 예외 없이 고정폭. 값이 바뀔 때 흔들리면 안 됨

### 7-3. 간격과 형태

```

모서리  카드 12px · 버튼 8px · 입력 8px · 배지 999px
테두리  1px --border(#23272E) · 강조 1px --border-strong(#343943)
그림자  없음 (다크에서 그림자는 안 보임). 층위는 배경색 단차로
최대폭  1280px 콘텐츠 · 1440px 셸
```

### 7-4. 시그니처 요소 — 스틴트 바

컴파운드 색 띠가 이 사이트의 시각적 정체성입니다. 로고, 카드, 트레이스 배경, 로딩
인디케이터에 일관되게 씁니다.

```
●━━━━━━━━━●━━━━━━━━━━━━━━━●     ← 로고 마크 (3스틴트 추상)

▓▓▓▓▓▓░░░░░░░░░░░░░░░░░░░░░     ← 트레이스 배경 음영
```

규칙: 컴파운드 색 요소는 **항상 1px `--bg-0` 외곽선**. 어떤 팀 컬러 위에서도 분리됨.

### 7-5. 이미지

- 드라이버·머신·로고: F1 공식 CDN (v2 `assets.js` 그대로). 실패 시 SVG 폴백

- 아이콘: 없음. 텍스트와 색으로 해결. 꼭 필요하면 인라인 SVG 16px

## 12. 콘텐츠 톤

v2 카피의 톤을 유지합니다. 규칙:

- **단정하되 겸손.** "~입니다" 종결. "~일 것입니다"는 불확실할 때만
- **숫자를 먼저.** "4.4초 유리합니다" — 형용사보다 수치
- **정직.** 근사값은 근사값이라고. "실측 캘리브레이션" 배지는 실버스톤에만
- **용어는 한국어 우선.** 언더컷·클리프처럼 굳어진 것만 외래어. 툴팁으로 보완
- **문장은 짧게.** 근거 한 문단은 3문장 이내

금지: 느낌표, "최고의", "혁신적인", "AI 기반" 같은 수식어.

## 16. 착수 전 확인

1. **이름 COMPOUND** — 팀 이름과 맞췄습니다. APEX를 유지하려면 말씀해주세요
2. **랩타임 차트 제거** — 트레이스만 남깁니다. 반대하시면 스텝 3에 탭으로 넣겠습니다
3. **연구 페이지 분량** — 10절은 많을 수 있습니다. 발표 시간에 맞춰 줄일 수 있습니다
4. **팀 페이지** — 팀원 사진을 넣을지, 이름·역할만 넣을지
