# 코덱스에게 줄 개선 프롬프트 (compound · https://juhyeonmoon10.github.io/compound/)

아래 블록을 그대로 붙여 넣는다. 각 절은 독립된 작업 단위라 하나씩 시켜도 된다.

---

당신은 https://juhyeonmoon10.github.io/compound/ 저장소(React + Vite, 단일 페이지, 탭: 추천 전략 / 직접 설계 / 상세 분석 / 3D 리플레이 / 실험 노트, 상단 메뉴: 홈 / 전략 설계 / 데이터 분석 / 알고리즘·검증 / 연구 정보)를 개선한다. 아래 순서대로 진행하고, 절마다 커밋을 나눈다. 기존 K-best 동적계획법과 "DP ↔ 완전탐색 PASS" 검사는 절대 깨지지 않아야 하며, 매 절이 끝날 때마다 그 검사를 다시 돌려 결과를 보고한다.

## 0. 공통 규칙

- 화면의 모든 글은 한국어. 장식용 영어 문구를 전부 제거하거나 실용 한국어로 바꾼다. 대상: `STRATEGY LAB`, `RACE STRATEGY / 2026`, `YOUR ENTRY`, `POSSIBLE RACE STRATEGIES`, `PLAN 01`, `EQUAL FASTEST`, `TWO-STOPPER`, `LAP 18 TO 23`, `WHITE HARD H`, `AVERAGE PIT STOP LOSS`, `DATA-DRIVEN F1 RESEARCH`, `REFERENCE SCENARIO`, `RACE WEEKEND SETUP`, `MULTI-RACE FASTF1 DATA`, `HOW IT WORKS`, `VERIFY THE CODE`, `LIVE TIMING`, `AUTO DRIVE · IDENTICAL BASE PACE` 등 섹션 라벨 전부. 컴파운드 약자 S/M/H 와 랩 표기 L21 은 남겨도 된다.
- "학교 프로젝트", "런포런", "발표", "탐구 보고서" 같은 표현을 화면과 README 에서 지운다. 비영리·비공식 고지는 남긴다.
- 숫자를 보여줄 때는 항상 그 숫자가 어디서 왔는지(실측 / 프로젝트 추정 / 공식 자료) 한 단어로 표시한다.
- 새 상수는 전부 한 파일(예: `src/model/params.ts`)에 모으고, 각 상수에 출처와 단위를 주석으로 단다.

## 1. 젖은 노면 — 인터미디어트·웨트 타이어

현재 모델은 건식 S/M/H 만 다룬다. 다음을 추가한다.

### 1-1. 상태 변수
- `water` ∈ [0, 1]: 노면 수막 수준. 레이스 조건에 `강수: 없음 / 약한 비 / 강한 비 / 마른 뒤 비 / 비 뒤 마름` 프리셋과 `비 시작 랩·끝 랩` 입력을 둔다.
- 매 랩 갱신: 비가 오는 동안 `water += rainRate`(약한 비 0.04 / 강한 비 0.10, 상한 1), 비가 그치면 `water -= dryRate × (1 + 0.5 × 트랙 위 차량 수/20)`(dryRate 기본 0.035/랩, 노면 온도 35°C 이상이면 ×1.3). 값은 프로젝트 추정으로 표시하고 상수 파일에 둔다.

### 1-2. 컴파운드
- `INTER`(초록), `WET`(파랑)을 추가한다. 랩타임 = 건식 기준 랩타임 + `wetPenalty(compound, water)`:
  - 슬릭(S/M/H): `water ≤ 0.10` 이면 +0.3·(water/0.10)초, 그 이상이면 +8초 + 30초 × (water − 0.10) (사실상 주행 불가).
  - INTER: 최적 구간 `0.15 ≤ water ≤ 0.55` 에서 +3.5초, 그보다 마르면 과열로 +0.25초/랩씩 누적(마른 노면 INTER 는 랩당 마모 0.12초), 그보다 젖으면 +6초 + 20초 × (water − 0.55).
  - WET: `water ≥ 0.55` 에서 +7초, 마르면 +0.4초/랩 누적.
  - 교차점(크로스오버)은 이 식에서 자연히 나온다. 화면에 "슬릭 ↔ 인터 교차: water ≈ 0.12, 인터 ↔ 웨트 교차: water ≈ 0.55" 처럼 계산된 교차 수막값을 표시한다.
- 마모: INTER 0.045초/랩, WET 0.035초/랩(프로젝트 추정). 클리프 없음 대신 과열 누적으로 처리.
- 워밍업: INTER·WET 은 첫 랩 페널티 없음(젖은 노면에서 바로 작동).

### 1-3. 규칙
- FIA 규정에 따라 레이스가 "젖은 레이스"로 선언되면 두 가지 건식 컴파운드 사용 의무가 사라진다. `rules.ts` 에서 `wetRace = water > 0.10 인 랩이 1랩 이상` 이면 두 컴파운드 규칙을 면제한다. 화면의 "규칙 통과" 판정 문구에 이유를 적는다.
- INTER·WET 로 출발하는 전략, 중간에 INTER 로 갈아타는 전략, 다시 슬릭으로 돌아오는 전략을 DP 상태에 넣는다. 상태 `c` 에 INTER/WET 을 추가하고, `mask` 는 건식 컴파운드만 센다. 최대 스톱 수는 젖은 조건에서 3까지 허용한다.

### 1-4. 데이터로 계수 잡기
- FastF1 로 2025 시즌 중 비가 온 레이스(예: 호주·영국·벨기에)의 랩을 받아 `Compound` 가 INTERMEDIATE/WET 인 랩과 같은 랩의 슬릭 랩을 비교해 위 페널티 상수를 보정한다. FastF1 `weather_data` 의 `Rainfall`, `TrackTemp`, `Humidity` 를 랩에 조인한다.
- 데이터 분석 탭에 "젖은 노면" 카드를 추가해 표본 랩 수, 인터 대비 슬릭 랩타임 차이의 분포, 교차 시점 관측값을 보여준다. 표본이 부족하면 "프로젝트 추정 유지"라고 표시한다(지금 건식에서 하는 방식과 같게).

### 1-5. 화면
- 추천 전략 보드의 타이어 아이콘에 INTER(초록)·WET(파랑)을 추가한다. 범례도 5종으로.
- 상세 분석 랩타임 차트 배경에 비 구간을 파란 띠로, 수막 수준을 얇은 선으로 그린다.
- 3D 리플레이에서 비가 오는 랩은 노면 반사와 스프레이 정도만 바꾸고(연출), 계산과 분리됐음을 지금처럼 명시한다.

## 2. 팀·드라이버 능력치

현재 "팀·선수 선택은 Top 3 계산에 영향 없음". 이를 선택형이 아니라 기본 반영으로 바꾼다.

### 2-1. 드라이버 — EA SPORTS F1 25 공식 레이팅
- 출처: https://www.ea.com/games/f1/ratings . 페이지는 JS 렌더링이라 HTML 파싱이 안 된다. `<script id="__NEXT_DATA__">` 의 JSON 에서 `ratingDetails.items` 배열을 읽는다. 반복(iteration) 이름과 확인 날짜를 데이터 파일에 기록한다(현재 "F1 25: 2026 Season Pack - June").
- 항목: OVR(종합), EXP(경험), RAC(레이스크래프트), AWA(인지), PAC(페이스). 22명 전원.
- 매핑(프로젝트 규칙, 상수 파일에 근거와 함께):
  - 랩당 페이스 보정 `driverPace = (88 − PAC) × 0.03` 초 (PAC 97 → −0.27초, PAC 78 → +0.30초)
  - 타이어 관리 계수 `mgmt = 1 − (EXP − 80) × 0.0015` → 마모 항에 곱한다
  - 젖은 노면 숙련 `wetSkill = 0.6 × OVR + 0.4 × AWA` → 1절의 wetPenalty 에 `× (1 − (wetSkill − 85) × 0.01)` 로 반영
  - 추월·수비 `racecraft = RAC` → 4절 교통 모델의 추월 성공 확률에 사용
- 2026 라인업이 EA 표기와 다른 경우(예: Hadjar 소속)는 데이터 파일에 주석으로 남기고 발표된 라인업을 따른다.

### 2-2. 팀(차량) 성능 — 공개 데이터에서 추정
- EA 는 차량 성능을 공개 페이지에 싣지 않는다. 대신 두 가지를 쓴다.
  1. 피렐리/F1 공식 전략 가이드 기사의 "Race Simulation Pace" 차트(팀별 최속 대비 초·%)를 최근 5경기 평균으로.
  2. FastF1 로 2025~2026 레이스의 팀별 정제 랩 중앙값을 최속 팀 대비 %로 계산(교통·SC·피트 랩 제외, 같은 컴파운드끼리).
- 결과를 `teamPace`(랩당 초, 최속 팀 0 기준)와 `teamDeg`(마모 배수, 0.9~1.15)로 두고, 두 출처의 값과 채택값을 표로 화면에 보여준다.
- 피트 크루: 2025 시즌 팀별 평균 정지 시간(공식 DHL 피트스톱 데이터 또는 FastF1 `PitOutTime − PitInTime` 에서 레인 통과분 제거)을 `pitCrew` 로.

### 2-3. 적용 방식
- 기본값은 반영. 헤더에 "동일 성능 모드" 토글을 두어 끄면 지금처럼 전략만 비교한다.
- 반영 결과 Top 3 가 바뀌는지 홈에 한 줄로 요약한다("페르스타펜·레드불 기준 1스톱이 0.8초 앞섬" 식).

## 3. 데이터 확장과 모델 반영

- 분석 레이스를 2025 건식 5경기에서 **2023~2025 최소 7서킷 20경기**로 늘린다. 같은 정제식·회귀식을 유지하고, 서킷별 계수 표에 연도별 표본 수를 함께 적는다.
- 지금처럼 95% 신뢰구간이 0을 벗어난 계수만 적용하되, 통과한 서킷 수를 5개 이상으로 늘리는 것이 목표. 통과 못 한 서킷은 "가장 비슷한 서킷(열화 등급이 같은)"의 계수를 대체값으로 쓰고 그렇게 표시한다.
- 피트 손실 함정: OpenF1/FastF1 의 피트레인 통과 시간(`lane_duration` 또는 `PitOutTime − PitInTime`)은 "잃은 시간"이 아니다. 실제 손실 = (인랩 + 아웃랩) − 2 × 정상 랩. 이 방식으로 24개 서킷 값을 다시 계산해 지금의 고정값과 나란히 표시하고, 차이가 3초 이상인 서킷은 실측값으로 바꾼다.
- 연료와 마모를 분리하는 회귀(`LapTime ~ Driver + RaceLap + RaceLap² + TrackTemp + Compound + Compound×TyreLife`)는 유지하되, `TyreLife²` 항을 넣어 클리프 시작 랩을 컴파운드별로 추정해 보고, 유의하면 `βca²` 계수로 쓴다.
- 홀드아웃 MAE 는 지금처럼 서킷별로 보고하고, 전체 평균(랩 수 가중)을 홈에 한 줄로.

## 4. 레이스 모델 — 결정론을 넘어서

지금 Top 3 가 셋 다 같은 시간(1:19:52.311)으로 나온다. 스틴트 순서만 바꾼 같은 답이다. 다음을 추가한다.

- **후보 중복 제거**: 컴파운드 집합과 각 스틴트 길이가 같고 순서만 다른 후보는 하나로 묶는다. Top 3 는 서로 스톱 수 또는 컴파운드 집합이 다르거나, 같은 경우 예상 시간이 0.5초 이상 차이 나야 한다.
- **세이프티카·VSC**: 서킷별 발생 확률(2018~2025 공식 기록 기준, 예: 모나코 0.7, 바레인 0.3)과 지속 랩 분포를 두고, 몬테카를로 300회를 돌린다. **한 회차 안에서는 모든 후보 전략에 같은 SC 타임라인을 준다**(안 그러면 운 차이가 전략 차이를 덮는다). SC 중 피트 손실은 정상의 약 55%. 결과는 "승률(가장 빠른 확률)"과 "P10–P90 완주 시간 폭"으로 보드 옆에 표시한다. 결정론 결과는 지금처럼 기본으로 두고 몬테카를로는 두 번째 줄로.
- **교통·언더컷**: 3D 리플레이에만 있는 20대 그리드를 전략 계산에도 쓴다. 앞차와 1.0초 이내이면 페이스 차 × 0.4 만큼 손실, 추월 성공 확률은 `racecraft`(2-1)와 페이스 차로 결정. 언더컷 판정은 "피트 직후 3랩은 정산 중으로 보고, 스톱 수가 같은 시점끼리만 순위를 비교"한다. 이 규칙 없이 비교하면 "상대가 방금 피트해서 25초 잃은 순간"을 역전으로 잡는다.
- 이 모든 확률 요소는 시드 고정으로 재현 가능해야 하고, "결정성 PASS" 검사를 시드 포함 형태로 유지한다.

## 7. 검증 항목 추가

- 기존 4개(DP↔완전탐색, 제약, 결정성, 시간 경계)에 추가: 연료 효과(마지막 랩이 첫 랩보다 1.2~3.0초 빠름), 클리프(소프트 25랩이 5랩보다 2초 이상 느림), 피트 랩 민감도(피트 랩 1랩 이동 시 총시간 변화 0.3초 이상), 젖은 노면 교차(water 0.12 근처에서 슬릭·인터 랩타임이 교차), 몬테카를로 재현성(같은 시드 → 같은 승률), SC 타임라인 공유(한 회차 안에서 모든 후보의 SC 랩이 동일).
- 백테스트를 3경기에서 7경기로 늘리고, 젖은 레이스 1경기(2025 영국 GP)를 포함한다. "모델 최적 대비 +x초" 옆에 "실제 순위" 대신 "실제 총시간 대비 모델 총시간 오차 %"를 같이 보여준다.

## 8. 실험 노트
